# 答案解析规则

适用源码版本：1.5.10；解析器：`free-text-v14`。

## 读取什么答案

平台按题目原有要求读取数字、选项、图示编号或文字。解析规则只处理模型返回内容，不向模型追加编号、JSON、槽位、回答数量或其他格式要求。

| 原题要求 | 保存方式 |
|---|---|
| 整数评分 | `answer` 保留提取内容，`score` 保存整数数值 |
| 数值或百分比 | 保存明确数值，保留允许的小数 |
| A/B、YES/NO、X 等选择 | 选择保存在 `answer`；不自动换算成数字分数 |
| 原文明确列出的选项文字 | 按该题明示对应关系读取选项，不猜测语义近似词 |
| 开放文字 | 保存文字，不要求数字，不自动评分 |
| IOS | 读取完整圆圈图示的选项编号 1–7 |
| 区间 | 保存原文及上下界，单一 `score` 留空，不取中点 |

因此，`score` 为空不代表未作答。应结合 `answer`、`parse_status` 和答案类型判断。

科尔伯格访谈按 Excel 的情境行保留开放文字；同一行内部的多个追问没有分别拆为独立答案字段。

## 题目如何对应

优先使用明确的情境、分节、原题文字和题号对应。完整无标记列表仅在数量、答案类型及必要范围全部相符时，按保存的实际发送顺序对应。不会截取多余列表的前若干项补满题目。

模型可能用原题号，也可能重新按发送顺序编号。两种解释无法区分时，仅提取两种对应下值相同的题目；其余保留原文，等待核对，不强行归题。

`mapping_method` 记录对应依据。原始模型回答保存在 JSON 的 `raw_response` 及完整回答 Excel 中；逐题 CSV 中未提取出答案的行仍会保存。

## 特殊任务

- **直觉推理**：第一任务 24 个逻辑判断读取 YES/NO，第二任务 16 个信念评分读取 −3 至 +3。两个任务各自乱序，仍在同一次请求发送；题号分别识别。只答第二任务时不补写第一任务。模型仅复述 `YES / NO` 等选项列表不算作选择。
- **人权敏感**：按情境与 I/II/III 分节定位；同一行用分号连接两个不同原题及其明确分数时，分别读取。
- **归因偏差**：按情境和 A/B/C 分节对应。兼容已观察到的“影响了她的行为／影响了他的行为”抄写差异，其他人物、属性及事件文字仍须一致。
- **宗教中心性**：按各题原有选项读取；原第 9、10、11 题为 1–8，其余为 1–5。把所有选项重新赋分的计分表不算作实际选择。

## 数值与缺失

整数题不把 3.5 四舍五入为整数；科学计数法整体读取；非有限数值不作为分数。越界值保留原值并标注 `out_of_range`，不作为符合原题范围的评分。

漏答、拒答、冲突回答、数量不符和无法确定题目归属的内容仍保留原始文本。已有解析规则不保证任意自由回答都能逐题对应；只保存试次文件也不等于答案已经成功提取。

## 旧结果重解析

更新源码后重启后台；旧 CSV 不自动改写。使用已保存的题目、提示文本和乱序顺序离线重解析，无需重新请求模型：

```text
python scripts/reparse_results.py <原结果目录> <新的空输出目录>
```

使用便携环境时，将命令中的 `python` 换为 `runtime\python.exe`。输出目录与原目录分开，原结果保持不变；添加 `--skip-excel` 可跳过完整回答 Excel 的生成。

源码包含离线回归检查，以及 `scripts/audit_answer_types.py` 和 `scripts/audit_decoder_results.py` 核验工具。量表、密钥、本机配置、原始研究回答和内部核验结果由使用者自行保管，不随公开源码提供。
